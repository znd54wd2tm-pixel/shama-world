# SHAMA WORLD V16

Версия от 20 октября 2026 года подготовлена из переданного `SHAMA_WORLD_V15_FIXED (1).zip`. Это доработка существующего проекта. Полное мастер-ТЗ ещё не выполнено: перечень готовых функций и ограничений находится в [REPORT_V16_RU.md](REPORT_V16_RU.md).

## Запуск

Нужен Python 3.12. Выполните команды из папки `shama-world-main`:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

В `.env` задайте действующие `BOT_TOKEN`, `WEBAPP_URL` и `DATABASE_PATH`. Для обновления укажите путь к **существующей** базе, а не к новой пустой копии. Ключ Supabase хранится только на сервере. `GAME_TIMEZONE=UTC` задаёт время торгов 08:00–00:00; другое имя часового пояса требует установленной базы часовых поясов IANA (в Windows при необходимости `python -m pip install tzdata`).

Перед обновлением остановите процессы, работающие с базой, и сохраните резервную копию:

```powershell
python manage.py backup
python manage.py migrate
python manage.py validate
python -m uvicorn routes:app --host 0.0.0.0 --port 8000
```

Приложение само запускает Telegram polling в production. Не запускайте одновременно отдельный `bot.py` с тем же токеном. Существующий `render.yaml` сохранён; Render использует постоянный диск `/var/data` и настроенную облачную копию Supabase. Боевой хостинг в этой работе не обновлялся.

Для просмотра в обычном браузере используйте отдельную тестовую базу и `python routes.py --dev --port 8766`. Режим `--dev` создаёт локального тестового пользователя, поэтому не используйте его на публичном сервере.

## Миграция и данные

Перед первым переходом создаётся `backups/<имя>.before-v16.<время>.sqlite3`. Пользователи и принадлежащие им объекты сохраняют ID. Старые кейсы архивируются; выпавшие ранее предметы не удаляются. Проданные государству предприятия остаются в истории с `retired=1`.

Скрипт миграции перестраивает ограничение уникальности таблицы предприятий внутри транзакции и проверяет внешние ключи. Ранее приобретённые кофейни получают комплект оборудования для сохранения работы. Изменение каталога и королевского пула выполняется однократно, последующие запуски не сбрасывают цены и вероятности.

`manage.py apply-config` из V15 для базы V16 отключён: он перезаписывал бы новый каталог. При откате восстанавливайте **вместе** прежний код и предмиграционную базу. Автоматического обратного преобразования новых операций в V15 нет.

## Проверка

```powershell
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
```

Браузерный прогон использует Playwright и Edge. Он выполняет настоящие игровые операции; запускать его можно только на изолированной локальной базе:

```powershell
python tools/prepare_browser_test.py
$env:DATABASE_PATH = "$PWD\.test-data\browser.sqlite3"
python routes.py --dev --port 8766
```

Во втором терминале:

```powershell
$env:PLAYWRIGHT_MODULE = 'абсолютный путь к node_modules/playwright'
node tests/browser-v16.cjs
```

Начинайте с новой `.test-data/browser.sqlite3`, чтобы все улучшения первого уровня были доступны. Торговые проверки запускаются в открытые часы рынка. Для Playwright при необходимости установите `npm install --no-save playwright` в отдельной папке инструментов. Результаты проведённых проверок и снимки находятся в `docs/validation/`.

## Изображения и параметры

Пять пользовательских JPEG подключены без изменения байтов; перечень и SHA-256 находятся в [docs/ASSETS_V16.md](docs/ASSETS_V16.md). Изображения для 62 предметов отсутствуют; новые картинки не сгенерированы. Панель «Нет изображения» не считается готовым ассетом. Старые SVG требуют отдельной оценки качества.

В `catalog_v16.py` находятся вероятности и банковские параметры. Для новых предметов не утверждён мгновенный выкуп: стоимость каталога не превращается в цену продажи автоматически. Их можно хранить, использовать в апгрейде и выставлять на рынок по цене продавца.

Для будущих предметных PNG предусмотрены стабильные `asset_key`, список ожидаемых файлов и `tools/bind_item_images.py`. Скрипт связывает реальные PNG с базой после резервного копирования; наличие файла не заменяет визуальную проверку качества.

Полный перечень новых и изменённых файлов относительно исходного FIXED-архива: [docs/CHANGESET_V16.txt](docs/CHANGESET_V16.txt). Документы V15 оставлены как историческая справка.
