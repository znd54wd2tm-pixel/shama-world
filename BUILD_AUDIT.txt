SHAMA WORLD V19 - AUDIT AND PATCH NOTES

Source
- Imported from SHAMA_WORLD_V19_CITY_UPGRADER_MAC_AUDITED.zip.
- BUILD_AUDIT in the archive described an older V18/V18.1 build; API health reports 19.0.
- SQLite database is created on startup as shama_world.db. No migration was needed for this patch.

Project map
- bot.py: aiogram /start handler and aiohttp static/API server.
- api_server.py: Telegram initData authentication and HTTP routes.
- database.py: SQLite schema, SH economy, case/drop catalog, inventory, upgrades, market, farm, missions.
- web/index.html: Telegram Mini App UI, navigation, case/upgrader/market/world interactions.
- web/assets/cases: four case illustrations.

Changes in this patch
- Mission start no longer returns route, hunt, or sequence answers as a `challenge` object.
- Added POST /api/world/missions/step. Route, hunt, and each factory-sequence choice are checked server-side.
- Legacy POST /api/world/missions/complete is retained but cannot grant rewards from a submitted full proof.
- Added lazy-loaded Three.js city with procedural buildings and clickable locations; the CSS map stays available if WebGL/CDN loading fails.
- Mission step regression test verifies hidden start data, rejection of full-proof completion, wrong-answer handling, and server-side reward completion.
- Telegram auth rejects timestamps more than 60 seconds in the future.
- /start escapes the Telegram display name before inserting it into HTML.
- Market and leaderboard views escape Telegram display names before rendering HTML.

Checks run
- Python syntax compilation: PASS.
- Inline JavaScript syntax: PASS (2 scripts).
- SQLite initialization and smoke flows: PASS (profile, case drop/save, farm, NPC market, all mission types).
- aiohttp route registration, Telegram /start integration, browser console, and mobile visual checks: NOT RUN.
- Runtime checks could not run because aiohttp and aiogram are not installed in the current environment. An isolated venv setup was attempted, but Windows path redirection under the Cyrillic user profile caused ensurepip to fail before package installation.
- Three.js rendering is syntax-checked but was not run in a browser. The lazy-loaded library is fetched from jsDelivr; the CSS map is the fallback.

Known gaps
- Three.js rendering still needs browser verification on desktop and mobile Telegram WebView.
- Existing catalog data is defined in database.py; inventory rows store copied item fields, so legacy records are not a fully normalized catalog reference.
- No user data or database file was present in the workspace during this audit; production SQLite data remains on its existing deployment volume.
- This audit did not execute the live Telegram bot or validate the Render deployment.
